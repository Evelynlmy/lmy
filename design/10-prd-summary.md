## 二、非功能性需求

### 性能要求

| 场景 | 指标 |
|------|------|
| 首页加载 | < 2秒（4G） |
| 搜索结果 | < 1.5秒 |
| 产品详情 | < 1.5秒 |
| 甲板图渲染 | < 3秒 |
| 支付发起 | < 1秒响应 |
| 支付回调 | < 5秒通知 |

### 兼容性要求

| 平台 | 要求 |
|------|------|
| iOS | iOS 14.0+ |
| Android | Android 8.0+ |
| 屏幕尺寸 | 375px ~ 414px（重点） |
| 网络 | 4G/WIFI，弱网降级 |

### 安全要求

| 项目 | 要求 |
|------|------|
| 用户数据 | 证件号脱敏展示 |
| 支付安全 | HTTPS + 支付签名验证 |
| 防刷单 | 评价需实名校验 |
| 防重复支付 | 幂等性校验 |

## 四、技术架构建议

```
前端：
  App: React Native（iOS + Android 双端）
  Mini Program: 微信小程序（营销活动）

后端：
  API Gateway → 微服务
  主要服务：用户服务 / 产品服务 / 搜索服务
           订单服务 / 支付服务 / 通知服务
           评价服务 / 房态服务

数据：
  产品/订单：MySQL
  搜索：Elasticsearch
  缓存：Redis（热门产品/房态）
  消息队列：Kafka（通知/支付回调）

三方集成：
  支付：微信支付 / 支付宝 / 银行卡
  通知：短信（阿里云）/ Push（极光/Firebase）
  地图：高德地图（停靠港口）
  保险：合作保险公司API
```

## 五、版本规划建议

### V1.0（MVP，建议3个月）
- P0全部功能
- 目标：跑通完整预订链路

### V1.5（建议+2个月）
- P1功能中的高频功能
- 岸上游、餐厅预约（增收）
- 目标：提升转化率和客单价

### V2.0（建议+3个月）
- P1剩余 + P2核心功能
- 会员积分体系
- 目标：提升复购和留存
