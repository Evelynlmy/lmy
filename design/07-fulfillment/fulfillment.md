# 履约链路设计文档

## 一、履约链路全貌

支付成功后，用户进入漫长的等待和出行期，产品需全程保持用户的「安全感」和「期待感」。

```
支付成功
  │
  ▼
等待成团（若为拼团产品）
  │
  ▼
成团通知 / 成团失败退款
  │
  ▼
行前准备阶段（出发前30天~1天）
  │  ├─ 出行准备提醒
  │  ├─ 登船证下载
  │  ├─ 岸上游选购
  │  └─ 餐厅/SPA预约
  ▼
登船日
  │  ├─ 行程激活
  │  └─ 在船服务入口
  ▼
行程中
  │  ├─ 每日行程推送
  │  ├─ 岸上游提醒
  │  └─ 在船消费记录
  ▼
下船日
  │
  ▼
行程结束（触发评价）
```

## 二、成团通知

### 2.1 成团机制说明

| 类型 | 说明 |
|------|------|
| 即时确认 | 支付即确认，无需等待成团 |
| 拼团产品 | 需满 N 人后成团（通常20-50人） |
| 预定金模式 | 先付定金锁位，余款在出发前30天结清 |

## 四、行前提醒时间轴

### 推送节点规划

```
支付成功        → 订单确认 + 引导行前准备
成团成功        → 成团通知 + 行前须知
距出发 30 天   → 登船证可下载提醒
距出发 21 天   → 岸上游/餐厅预订提醒
距出发 14 天   → 行前准备清单推送
距出发 7 天    → 出发倒计时 + 天气预报
距出发 3 天    → 重要提醒（证件/行李清单）
距出发 1 天    → 出发提醒 + 登船指南
出发当天       → 登船指南 + 地图
```

## 六、订单状态机

```
待支付
  ↓ 支付成功
待成团（拼团产品）/ 已确认（即时确认）
  ↓ 成团成功
已确认
  ↓ 出发日到达
进行中
  ↓ 行程结束
待评价
  ↓ 完成评价（或超时）
已完成
```

**异常状态：**
```
待支付 →（超时）→ 已取消
待成团 →（未成团）→ 已退款
已确认 →（用户申请）→ 退款中 → 已退款
```
